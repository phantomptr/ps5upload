# One-button Backport Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a user backport a folder-installed game from Games in one flow, using libraries from another installed title and an overlay owned by the ps5upload payload.

**Architecture:** Keep firmware/library matching and apply/undo orchestration as pure client modules over existing RPCs. Extend the SDK scan response with the payload overlay state instead of adding another protocol, and run a small payload lifecycle watcher that mounts `<sandbox>/app0/fakelib` over the active sandbox library directory.

**Tech Stack:** C/FreeBSD payload, Rust protocol/engine bridge, TypeScript/React/Vitest client.

**Spec:** `docs/superpowers/specs/2026-09-08-backport-design.md`

## Global Constraints

- Target SDK pair is exactly `(0x04000031, 0x09040001)`.
- Never copy or distribute Sony libraries; donors are installed folder titles.
- Never remove or overwrite a library already present in the target.
- Never perform an SDK-only apply when no donor libraries fit.
- `libc.prx` patch remains opt-in and defaults off.
- Encrypted retail SELFs remain unpatchable.
- Undo removes only files recorded as copied by ps5upload and restores existing `.bak` files.
